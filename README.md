# NLP Customer Support Intent Classification & Routing System

A business-oriented NLP portfolio project that routes fine-grained customer-support queries to the correct banking support intent while escalating ambiguous cases to human review.

## Business problem

Customer support teams receive short, noisy messages such as "my transfer never arrived" or "why was I charged twice?". A production system should not merely output a class label; it should decide when the model is reliable enough to auto-route and when a human should review the case.

The end-to-end workflow is:

```text
customer query
  -> text validation
  -> TF-IDF baseline
  -> TensorFlow BiLSTM benchmark
  -> PyTorch/Hugging Face Transformer
  -> class-level error analysis
  -> confidence-based routing
  -> auto-route vs human review
```

## Dataset

BANKING77 contains 13,083 English online-banking customer-service queries across 77 fine-grained intents. The official split is 10,003 train and 3,080 test examples. The official test set is reserved for final evaluation; a stratified validation set is created only from the training split.

## Why three model families?

- **TF-IDF + Logistic Regression (scikit-learn)**: cheap, interpretable baseline that tests whether lexical features are already sufficient.
- **BiLSTM (TensorFlow/Keras)**: lightweight neural sequence benchmark that learns task-specific dense representations.
- **DistilBERT (PyTorch + Hugging Face Transformers)**: pretrained contextual language model for semantically overlapping intents.

The goal is not to collect frameworks. The comparison answers whether extra representation complexity produces enough incremental value to justify production cost.

## Evaluation

Headline metrics:
- accuracy
- macro-F1 across 77 intents
- per-class precision/recall/F1
- top confusion pairs
- confidence / calibration diagnostic
- auto-routing coverage
- accuracy among auto-routed cases
- human-review rate

## Routing policy

A model only auto-routes a query when its maximum predicted probability exceeds a validation-selected threshold. The threshold maximizes automation coverage subject to a target accuracy requirement on auto-routed validation cases. Lower-confidence requests are escalated to humans.

## Reproducibility

`ci.yml` runs lightweight unit tests on every push/PR. `full-analysis.yml` installs TensorFlow and Transformers and trains all three model families before producing verified artifacts and `RESULTS.md`. The Transformer benchmark uses the full official training split with a one-epoch fine-tuning run so the workflow remains reproducible on a CPU GitHub runner.
